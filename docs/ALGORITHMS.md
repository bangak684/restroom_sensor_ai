# 알고리즘 설명서: 통합 화장실 판정 모델

이 문서는 화장실 센서 상자 하나로 16개 항목을 판정하는 통합 모델(`restroom_unified/`)을 설명합니다.

- 어떤 알고리즘을 썼는지, 각 알고리즘이 어떻게 동작하는지
- 실제로 어떻게 튜닝했는지 (값과 결과 포함)
- 앞으로 어떻게 튜닝할 수 있는지 (어디를 바꾸면 무엇이 달라지는지)

마지막 장에는 이 모델이 대신하는 원래 캡스톤 프로젝트의 세 모델(시설 AI, 흡연 판정기, Duo Fusion)도 같은 형식으로 요약했습니다. 학습 과정과 실제 실행 기록은 [TRAINING.md](TRAINING.md)에 있습니다.

> **모든 수치는 합성 데이터 결과입니다. 실제 화장실 측정은 0행입니다.** 학습 데이터는 [`data/unified_world_v1/`](../data/unified_world_v1/README.md)에 있습니다.

## 0. 한눈에 보기

```
 센서 상자 (15초마다 한 행)
 DHT11 온도·습도 + MQ-135 + MQ-7
        │
        ▼
 ① 특징 만들기 (features.py)          과거 값만 쓰는 이동 창 계산 → 특징 56개
        │
        ▼
 ② 판정 모델 (model.py)               HistGradientBoosting 이진 분류기 16개 → 항목별 확률 16개
        │
        ▼
 ③ 판정 규칙 (model.py, rules.py)     항목별 임계값 · 흡연 알림 지속 규칙 · 등급 규칙
        │
        ▼
 결과: 등급(긴급/주의/정보/평상시), 대표 문구, 켜진 항목, 확률, 흡연 경보/의심, 동파 단계
```

| 단계 | 알고리즘 | 튜닝한 것 |
|---|---|---|
| 데이터 | 물리 기반 합성 시뮬레이션 (1차 혼합 모형 + 확률적 사건 + 센서 모형), 장치마다 파라미터 무작위화 | 동파 항목이 너무 드물어 겨울 장치 비율을 올림 |
| 특징 | 인과적 이동 창 통계, 전도도 변환, 깨끗한 공기 기준선, MQ-7 히터 주기 처리, 기기 자기 보정 | 창 길이는 설계값 (튜닝하지 않음) |
| 모델 | 히스토그램 기반 그래디언트 부스팅 결정 트리 (scikit-learn `HistGradientBoostingClassifier`), 항목마다 하나 | 잎 노드 수(격자 탐색), 항목별 반복 횟수(보정 장치에서 조기 종료) |
| 임계값 | 정밀도-재현율 곡선에서 선택 | 항목별 F1 최대 임계값(경보), 정밀도 50% 이상 중 가장 민감한 임계값(주의) |
| 흡연 알림 | "최근 n번 중 m번 이상" 지속 규칙 + 해제 지연 | 오경보 상한 아래에서 감지율 최대인 규칙 (격자 탐색) |
| 등급 | 사람이 정한 규칙 (항목끼리 교차 확인) | 초안 값 (실측으로 정해야 함) |

## 1. 데이터: 통합 합성 세계 (`world.py`)

### 1.1 왜 새 데이터가 필요했나

기존 두 연구의 합성 데이터는 서로 다른 세계였습니다.

- 습도 형식이 다름: 한쪽은 정수, 한쪽은 소수
- 한쪽에는 창문 사건이 없고, 다른 쪽에는 MQ-7 채널이 없음
- 문 열림은 어느 쪽에도 제대로 모형화되지 않음

그래서 두 모델을 합쳐 돌리면 창문 오경보가 27%까지 났습니다. 하나의 모델을 학습하려면 **모든 항목의 정답이 같은 시계열에 함께 있는 데이터**가 필요했습니다.

### 1.2 시뮬레이션 방식

장치(화장실) 하나마다 물리 상태를 15초 간격으로 계산합니다. 모든 식은 **1차 혼합 모형**입니다. 매 단계마다 현재 값이 목표 값 쪽으로 일정 비율만큼 다가갑니다.

**온도**

```
T ← T + a_th·(설정온도 − T) + k_win·창문·(바깥온도 − T) + k_door·문·(복도온도 − T)
```

**습도** (기본 습도 + 세 가지 초과분)

```
H_기본 ← H_기본 + a_h·(설정습도 − H_기본) + k_win·창문·(바깥습도 − H_기본) + k_door·문·(복도습도 − H_기본)
hx (손 씻기·물 사용 등 짧은 습기) ← hx + 주입량 − hx·(kh + k_hdoor·문 + 0.02·환풍기)
hw (젖은 바닥) ← hw + 0.006·(목표 − hw)
hl (누수) ← hl + 0.01·(목표 − hl)
H = H_기본 + hx + hw + hl   (5~99%로 자름)
```

**가스** (c1 = 냄새·VOC → 주로 MQ-135, c2 = 일산화탄소 계열 → 주로 MQ-7, 연기 추적 농도 s)

```
c ← c + 주입량 − c·(k0 + k_fan·환풍기 + k_gdoor·문 + k_gwin·창문)
```

문, 창문, 환풍기가 열리거나 켜지면 가스가 더 빨리 빠집니다.

**센서**

| 센서 | 모형 |
|---|---|
| MQ-135 | 전도도 G = G0 × 드리프트 × (1 + a135·c1 + 0.1·c2) × (1 + 습도 계수·(H−50)) × (1 − 0.004·(T−20)) × (1 + 잡음 1.5%) |
| MQ-7 | 전도도 G = G0 × 드리프트 × (1 + bco·c2 + bodor·c1) × (1 + 습도 계수·(H−50)) × (1 + 잡음 2.5%) |
| ADC | `4095 × G / (1 + G)` + 잡음, 12비트 정수. 거꾸로 `adc / (4095 − adc)`를 하면 전도도가 나옵니다 |
| MQ-7 히터 | 150초 주기 중 마지막 60초(4행)만 읽을 수 있음. 나머지 행은 값 없음 |
| DHT11 | 정수로 반올림, 온도 0~50℃, 습도 20~90%로 자름, 장치별 고정 오차(표준편차 온도 0.8℃, 습도 2.5%p) + 측정 잡음 |

**날씨와 난방**

- 기후 3종(연평균 약 3℃, 12℃, 21℃), 계절 변화, 일교차, 며칠 단위 날씨 변동(AR(1))이 있습니다.
- 난방 고장(3~12시간)과 난방 없는 방이 있어 동파 위험이 생깁니다.

**사건** (하루 기준)

| 사건 | 빈도 | 길이 | 센서에 주는 영향 |
|---|---|---|---|
| 이용 | 15~60번 (주말 60%) | 1~5분 | 출입할 때 문 열림, 70%는 냄새(c1, CO는 냄새의 2~15%, 2%는 20~80%), 70%는 손 씻기로 이어짐 |
| 손 씻기 | 이용의 70% | 20~60초 | 습기 주입, 수도 사용, 20%는 소독제(냄새 조금 + CO 조금) |
| 흡연 | 장치의 25%는 0, 나머지는 중앙값 약 0.8번(0.1~6번, 주말 70%) | 2~10분 | 냄새와 CO를 함께 많이 주입(CO는 냄새의 20~100%), 센서까지 오는 양은 장치마다 다름 |
| 청소 | 1~3번 (아침·점심·저녁) | 5~15분 | 냄새 많이(CO 1~6%), 절반은 문 열어 둠, 60%는 물청소(젖은 바닥 10~25분 더) |
| 물 쏟음 | 약 1번 | 15~45분 | 젖은 바닥(습도 서서히 오름) |
| 방향제 | 장치의 40%에서 평균 1~4번 | 15~60초 | 냄새 조금 |
| 물 사용 | 약 3번 | 10~40초 | 짧은 습기, 수도 사용 |
| 문만 열림 | 약 4번 (짧게), 0.3번 (10~60분 열어 둠) | 8초~60분 | 복도 공기와 교환 |
| 창문 | 창문 있는 장치(65%), 날이 따뜻할수록 자주 | 5분~6시간, 가끔 3~9시간 방치 | 바깥 공기와 교환 |
| 환풍기 강풍 | 환풍기 있는 장치(70%)에서 약 2.5번 | 10~40분 | 가스가 빨리 빠짐 |
| 누수 | 장치에 따라 하루 1.5~12.5% 확률 | 20분~5시간 | 습도가 크게, 천천히 오름 |

**장치마다 다른 파라미터 (도메인 무작위화)**

시간 상수, 문·창문 교환율, 복도와 방의 온습도 차이, 센서 감도와 기준선, 연기가 센서에 오는 정도, 이용 빈도, 흡연 빈도를 장치마다 무작위로 정합니다. 모델이 특정 장치의 값을 외우지 못하고, 장치가 바뀌어도 유지되는 패턴을 배우게 하려는 것입니다.

### 1.3 데이터 나누기

| 구분 | 시드 | 장치 | 쓰는 곳 |
|---|---|---|---|
| train | 1 | 120대 × 14일 | 학습 (8행마다 1행 표본, 119만 행) |
| calibration | 2 | 40대 × 14일 | 반복 횟수·임계값·흡연 규칙 고르기 |
| test | 3 | 40대 × 14일 | 최종 시험 (같은 세계, 처음 보는 장치) |
| shift | 4 | 40대 × 14일 | 분포 이동 시험: 추운 곳 많음, 센서 감도 차이 2배, 복도 온습도 차이 방향 반대, 연기 절반, 이용 1.5배 |

장치는 구분 사이에 겹치지 않습니다. 처음 2시간(예열)과 마지막 3시간(동파 미래 정답 없음)은 학습·평가에서 뺍니다.

## 2. 특징 만들기 (`features.py`)

모델은 원시 센서값이 아니라 **특징 56개**를 봅니다. 모든 특징은 **과거 값만** 씁니다(인과적). 그래서 실시간으로 한 행씩 들어와도 같은 값을 계산할 수 있습니다.

### 2.1 핵심 아이디어

| 아이디어 | 방법 | 이유 |
|---|---|---|
| 전도도로 바꾸기 | `g = adc / (4095 − adc)` | ADC 값은 가스가 많을수록 포화되지만, 전도도는 가스 양에 거의 비례해서 오릅니다 |
| 깨끗한 공기 기준선 | MQ-135는 2분 평균의 최근 2시간 최솟값, MQ-7은 읽은 값의 최근 2시간 최솟값 | 장치마다 다른 센서 기준선과 느린 드리프트를 지웁니다. 특징은 "기준선 대비 몇 % 올랐나"가 됩니다 |
| MQ-7 히터 주기 | 읽을 수 있는 행만 쓰고, 마지막 값을 최대 30행(7.5분) 유지, 마지막 읽기 후 경과 행 수도 특징으로 줌 | MQ-7은 150초 중 60초만 의미 있는 값을 냅니다 |
| 냄새 대비 CO 비율 | `MQ-7 상승 ÷ MQ-135 상승` | 흡연만 두 센서가 함께 크게 오릅니다. 냄새·청소는 MQ-135만 오릅니다 |
| 기기 자기 보정 | 최근 6시간 동안 가스 사건(MQ-135 +20% 이상) 때의 CO 비율 중앙값 = 그 기기의 "평소 냄새 비율" | 냄새 사건이 흡연보다 훨씬 많아서, 중앙값이 곧 그 기기의 평소 값이 됩니다. 현재 비율이 평소의 몇 배인지 봅니다. 해당 행이 4개 미만이면 0.074를 씁니다 |
| 온습도 변화 속도 | 1분·5분·15분·1시간 변화량, 2행 전과의 차이, 2분 안 최대 급변 | 문·창문 열림(빠르게 떨어짐), 손 씻기(급히 오름), 누수(천천히 계속 오름)를 구분합니다 |
| 시간 | 시각·계절의 sin/cos, 주말 | 이용 패턴과 동파 계절성 |

### 2.2 특징 목록 (56개)

| 묶음 | 개수 | 특징 |
|---|---|---|
| 온도 | 14 | 1분 평균, 1분·5분·15분·1시간 변화, 2행 전과의 차이, 2분 안 최대 급변, 1시간 평균·최대, 3시간 최저, 6시간 평균과의 차이, 30분 범위, 15분 기울기, 최근 3시간 중 3℃ 이하였던 시간 |
| 습도 | 14 | 1분 평균, 1분·5분·15분·1시간 변화, 2행 전과의 차이, 2분 안 최대 급변, 1시간 평균·최대·최소, 30분 평균 대비 상승, 6시간 평균과의 차이, 최근 3시간 중 85% 이상이었던 시간, 30분 최고점과의 차이 |
| 시간 | 5 | 시각 sin/cos, 계절 sin/cos, 주말 |
| MQ-135 | 10 | 1분·3분 상승률, 10분·30분 최대 상승, 30분 평균 상승, 3분 기울기, 2분 감쇠 속도, 30분 최고점과의 차이, 150초 평균 상승, 기준선 6시간 드리프트 |
| MQ-7 | 13 | 최근 상승률, 한 주기 전 상승률, 3주기 최대, 150초 평균, 마지막 읽기 후 경과, CO 비율, CO 초과량(상승 − 0.1 × MQ-135 상승), 기기 평소 비율, 평소 대비 비율, 기기 기준 CO 초과량과 3주기 최대·합, 3주기 최대 ÷ MQ-135 상승 |

온습도와 시간만 쓰는 33개는 `CLIMATE_FEATURES`로 따로 묶여 있습니다. 가스 센서 없이 온습도만으로 얼마나 판정되는지 비교할 때 씁니다(6장).

### 2.3 실시간 계산 (스트리밍)

- `FeatureStream`은 최근 2,400행(10시간)을 보관하고, 행이 들어올 때마다 같은 함수로 마지막 행의 특징을 계산합니다.
- 가장 긴 계산은 "2시간 기준선 위에서 만든 비율의 6시간 중앙값"이라서 최소 약 1,920행이 필요합니다. 버퍼 2,400행은 이것을 넉넉히 덮습니다.
- 그래서 실시간 계산과 한꺼번에 계산(학습 때)의 특징값이 **정확히 같습니다**(`check.py`에서 확인).
- 처음 480행(2시간)은 "준비 중"으로 판정하지 않습니다.

## 3. 판정 모델: 히스토그램 기반 그래디언트 부스팅 (`model.py`, `train.py`)

### 3.1 구조

- 16개 항목마다 **이진 분류기 하나**를 학습합니다(항목이 켜져 있나 / 아닌가).
- 16개는 같은 특징 56개를 입력으로 받고, 하나의 파일(`models/unified/unified_model.joblib`)로 묶여 `UnifiedModel` 하나로 동작합니다.
- 한 행에 여러 항목이 동시에 켜질 수 있으므로(다중 라벨), 항목마다 따로 확률을 냅니다.

### 3.2 그래디언트 부스팅이란

작은 결정 트리를 하나씩 차례로 더해 가는 방법입니다.

1. 처음에는 모든 행에 같은 점수(로그 오즈)를 줍니다.
2. 현재 점수로 계산한 손실(이진 교차 엔트로피)의 **기울기(gradient)와 곡률(hessian)**을 행마다 구합니다. 기울기는 "이 행의 점수를 어느 쪽으로 얼마나 고쳐야 하나"입니다.
3. 이 기울기를 가장 잘 설명하도록 새 트리 하나를 만듭니다.
4. 새 트리의 출력에 학습률(0.08)을 곱해 점수에 더합니다.
5. 2~4를 정해진 횟수(반복 횟수)만큼 되풀이합니다. 최종 점수에 시그모이드를 씌우면 확률이 됩니다.

트리 하나하나는 약하지만, 앞 트리들이 틀린 부분을 다음 트리가 고치므로 합치면 강해집니다.

### 3.3 "히스토그램 기반"이 하는 일

| 기능 | 설명 |
|---|---|
| 구간 나누기 | 특징값을 최대 255개 구간으로 미리 나눕니다. 분할 후보를 구간 경계만 보면 되므로 수백만 행도 빠릅니다 |
| 잎 우선 성장 | 트리를 깊이 순서가 아니라 **이득이 가장 큰 잎부터** 나눕니다. 잎 수 상한(`max_leaf_nodes`)에서 멈춥니다 |
| 분할 기준 | 이득 = G_L²/(H_L+λ) + G_R²/(H_R+λ) − G²/(H+λ). G는 기울기 합, H는 곡률 합, λ는 L2 규제입니다 |
| 잎 값 | −G/(H+λ) × 학습률 (뉴턴 방법 한 걸음) |
| 빈 값 처리 | 분할할 때마다 빈 값(NaN)을 왼쪽·오른쪽 중 이득이 큰 쪽으로 보내도록 배웁니다. MQ-7 값이 없는 행, 예열 직후의 짧은 이력을 따로 채우지 않아도 됩니다 |
| 클래스 가중치 | `class_weight="balanced"`: 드문 쪽(켜짐)의 행에 `전체 행 수 / (2 × 그 클래스 행 수)` 가중치를 줍니다. 흡연(0.35%)처럼 드문 항목도 학습에서 무시되지 않습니다 |

### 3.4 왜 이 알고리즘인가

- 표 형식 데이터(특징 56개)에서 신경망보다 적은 데이터·시간으로 높은 성능을 내는 경우가 많습니다.
- 빈 값을 스스로 처리합니다(MQ-7 히터 주기 때문에 빈 값이 많음).
- 특징의 크기·단위를 맞출 필요가 없습니다.
- 기존 시설 AI가 같은 알고리즘이라 비교하기 쉽고, scikit-learn만 있으면 됩니다(XGBoost·Torch 불필요).
- 모델이 작고(16개 합쳐 15MB) 예측이 빠릅니다(행 하나에 16개 모델 합쳐 약 45ms).

## 4. 판정 규칙

### 4.1 항목별 임계값

모델은 확률을 냅니다. 확률이 **임계값 이상이면 그 항목이 켜졌다**고 판정합니다. 임계값은 보정 장치 40대의 모든 행에서 항목마다 두 개를 고릅니다.

| 이름 | 고르는 방법 | 쓰는 곳 |
|---|---|---|
| `alarm` | 정밀도-재현율 곡선에서 **F1이 가장 큰** 임계값 | 모든 항목의 켜짐 판정, 동파 "경보" |
| `watch` | 정밀도가 **50% 이상**인 임계값 중 가장 낮은(가장 민감한) 값. `alarm`보다 높지 않게 | 동파 "주의" (놓치면 안 되므로 민감하게, 단 알림의 절반 이상은 맞게) |

### 4.2 흡연 알림 지속 규칙

흡연 확률이 한 번 튀었다고 바로 알리면 오경보가 많습니다. 그래서 **지속 규칙**을 씁니다.

- 조건: 최근 `window`번 판정 중 `m`번 이상 흡연 확률이 `threshold` 이상
- 알림은 조건이 마지막으로 성립한 뒤 `clear`번(8번 = 2분) 판정 동안 유지
- 두 단계: **흡연 경보**(긴급, 엄격)와 **흡연 의심**(주의, 민감)

규칙 값은 보정 장치에서 격자 탐색으로 고릅니다(5.5절). 평가 기준은 사건 단위입니다.

- **잡음:** 흡연 시작부터 끝난 뒤 5분 사이에 알림이 한 번이라도 켜짐
- **오경보:** 알림이 켜진 시점의 10분 전 ~ 5분 후에 흡연이 없음. 장치·일당 횟수로 셉니다

### 4.3 등급 규칙 (`rules.py`)

켜진 항목들을 보고 사람이 얼마나 신경 써야 하는지 정합니다.

## 5. 실제로 한 튜닝

순서대로 진행했습니다. 모든 선택은 **보정 장치(calibration)**에서만 했고, 시험 장치(test, shift)는 마지막에 한 번만 평가했습니다.

### 5.1 데이터 쪽 조정

| 문제 | 조정 |
|---|---|
| 첫 생성에서 동파 항목이 0.1%로 너무 드묾 (장치 40대 중 4대) | 장치의 40%를 겨울(12월 초~2월 중순)에 시작하게 하고, 추운 곳의 난방 없는 방(12%)과 난방 고장 확률(하루 최대 12%)을 올림 → 동파 1시간 0.86%, 3시간 1.15% |
| 학습 행이 너무 많음 (967만 행) | 8행마다 1행 표본(119만 행). 15초 행은 이웃끼리 매우 비슷해서 정보 손실이 적습니다 |
| 드문 항목 (흡연 0.35%, 방향제 0.25%) | `class_weight="balanced"` |

### 5.2 잎 노드 수: 격자 탐색

- 대표 항목 4개(흡연, 문 열림, 창문 열림, 누수)로 학습 행 30만 개를 뽑아, 잎 노드 수 15, 31, 63을 비교했습니다.
- 각 후보는 최대 300번 반복하면서 보정 장치의 평균 정밀도(AP)가 가장 좋을 때의 값으로 비교했습니다.

| `max_leaf_nodes` | 보정 장치 평균 AP (4개 항목 평균) |
|---|---|
| 15 | 0.6133 |
| 31 | 0.6195 |
| **63 (선택)** | **0.6238** |

### 5.3 항목별 반복 횟수 (보정 장치로 조기 종료)

### 5.4 임계값

보정 장치 40대의 모든 행(317만 행)에서 골랐습니다. `watch`는 동파 "주의" 단계에만 씁니다.

| 항목 | alarm (F1 최대) | watch (정밀도 50% 이상 중 가장 민감) |
|---|---|---|
| 흡연 | 0.963 | 0.878 |
| 흡연 후 잔류 | 0.935 | 0.563 |
| 이용·냄새 | 0.872 | 0.294 |
| 손 씻기·습기 | 0.886 | 0.593 |
| 젖은 바닥 | 0.800 | 0.771 |
| 청소 제품 | 0.936 | 0.771 |
| 청소+젖은 바닥 | 0.907 | 0.869 |
| 소독제 | 0.928 | 0.908 |
| 방향제 | 0.821 | 0.821 |
| 문 열림 | 0.823 | 0.823 |
| 창문 열림 | 0.846 | 0.748 |
| 환기 변화 | 0.858 | 0.858 |
| 수도 사용 | 0.924 | 0.896 |
| 누수 | 0.352 | 0.013 |
| 동파 1시간 | 0.989 | 0.007 |
| 동파 3시간 | 0.994 | 0.586 |

- 대부분 0.8~0.99로 높습니다. `class_weight="balanced"`로 드문 항목에 가중치를 줘서 확률이 실제 비율보다 높게 나오기 때문입니다. 임계값을 보정 장치에서 다시 고르므로 판정에는 문제가 없습니다.
- 누수는 0.35로 낮습니다. 누수 확률은 "확실히 누수"일 때만 높게 나오고 나머지는 거의 0이라, 낮은 임계값에서도 오경보가 적습니다.
- 문 열림, 방향제, 환기 변화는 `watch`와 `alarm`이 같습니다. 정밀도 50%를 넘는 더 민감한 임계값이 없다는 뜻입니다.

### 5.5 흡연 알림 규칙

보정 장치에서 고른 규칙입니다(임계값 12개 × 지속 조건 9개 = 108개 후보).

| 단계 | 규칙 | 오경보 상한 | 보정 장치 감지율 | 보정 장치 오경보 (장치·일당) | 알림까지 (중앙값 / 90%) |
|---|---|---|---|---|---|
| 흡연 경보 (긴급) | 확률 0.98 이상이 최근 12번(3분) 중 10번 | 0.05 | 61.8% | 0.049 | 4.0분 / 6.4분 |
| 흡연 의심 (주의) | 확률 0.97 이상이 최근 8번(2분) 중 6번 | 0.25 | 79.5% | 0.234 | 3.0분 / 5.5분 |

두 단계 모두 알림은 조건이 마지막으로 성립한 뒤 8번(2분) 동안 유지됩니다.

### 5.6 고정한 값 (튜닝하지 않음)

| 값 | 설정 | 이유 |
|---|---|---|
| 학습률 | 0.08 | 반복 횟수를 항목별로 고르므로 학습률은 하나로 고정했습니다 |
| 잎 최소 행 수 (`min_samples_leaf`) | 100 | 119만 행에서 너무 작은 잎(과적합)을 막는 보수적 값 |
| L2 규제 (`l2_regularization`) | 1.0 | 잎 값을 조금 줄여 안정화 |
| 구간 수 (`max_bins`) | 255 (기본값) | DHT11은 정수라 255구간이면 충분 |
| 특징 창 길이 | 1분~6시간 | 사건 길이(15초~수 시간)를 덮도록 설계한 값 |
| 등급 규칙 숫자 | 30분, 3℃, 12~2월 | 실측 전 초안 |

### 5.7 시행착오

- **반복 횟수 자르기:** scikit-learn의 `n_iter_`는 쓸 수 없는 속성이라, 학습된 트리 목록(`_predictors`)을 앞에서부터 잘라 반복 횟수를 줄입니다. 잘라도 그 횟수에서의 예측과 같습니다.
- **흡연 규칙 탐색 범위가 좁았음:** 첫 전체 학습에서 흡연 규칙 후보의 임계값이 최대 0.9였습니다. 그런데 `class_weight="balanced"` 때문에 흡연이 아닌 행도 확률이 0.9를 넘는 경우가 많아, 오경보 상한을 맞추는 후보가 하나도 없었습니다(경보·의심이 같은 기본 규칙으로 대체됨). 임계값을 0.995까지, 지속 조건을 16번 중 14번까지 넓히고 다시 골랐습니다. 이제 기준을 맞추는 후보가 없으면 오경보가 가장 적은 규칙을 쓰고 그 사실을 기록합니다.
- **동파 "주의" 단계가 항상 켜질 뻔함:** 처음에는 `watch`를 "재현율 90% 이상인 가장 높은 임계값"으로 골랐습니다. 동파 1시간은 그 값이 0.000이 됐습니다. 난방 고장처럼 갑자기 시작되는 동파 위험은 센서로 미리 볼 수 없어서, 재현율 90%를 맞추려면 모든 행을 "주의"로 해야 했기 때문입니다. 기준을 "정밀도 50% 이상 중 가장 민감한 임계값"으로 바꿨습니다(시험 장치에서 동파 1시간 주의: 정밀도 74%, 재현율 82%).
- 두 문제 모두 모델을 다시 학습하지 않고 `retune`으로 임계값과 규칙만 다시 골라 고쳤습니다.

- **보통 (F1 0.5~0.7):** 청소, 동파 3시간, 흡연(행 단위), 소독제, 젖은 바닥, 수도 사용. 다른 사건과 신호가 겹칩니다. 흡연은 행 단위보다 사건 단위(6.2절)가 실제 쓰임새에 맞습니다.
- **약함 (F1 0.4 이하):** 문 열림, 창문 열림, 환기 변화, 방향제. 신호가 작거나(방향제), 가스·온습도 변화가 다른 사건에 묻힙니다.

### 6.2 흡연: 사건 단위

| 장치 | 단계 | 흡연 사건 | 잡은 비율 | 오경보 (장치·일당) | 알림까지 (중앙값 / 90%) |
|---|---|---|---|---|---|
| 시험 (test) | 흡연 경보 | 568 | **57.4%** | 0.051 (약 20일에 1번) | 4.3분 / 6.4분 |
| 시험 (test) | 흡연 의심 이상 | 568 | **76.2%** | 0.167 (약 6일에 1번) | 3.0분 / 5.5분 |
| 분포 이동 (shift) | 흡연 경보 | 286 | 39.2% | 0.054 | 4.0분 / 6.2분 |
| 분포 이동 (shift) | 흡연 의심 이상 | 286 | 63.3% | 0.218 | 3.3분 / 6.5분 |

기존 흡연 판정기(다른 합성 세계, 흡연 의심 이상 89.2%)보다 낮습니다. 이 세계는 흡연 연기가 센서까지 오는 양이 장치마다 크게 다르고(연기 절반 이하인 장치 많음), 흡연 중 문이 열리고 손 씻기가 이어지는 등 다른 사건이 겹치게 만들었기 때문으로 보입니다.

### 6.3 분포 이동 시험 (shift)

학습과 다른 조건(추운 곳 많음, 센서 감도 차이 2배, 복도 온습도 차이 방향 반대, 연기 절반, 이용 1.5배)의 장치 40대입니다.

| 항목 | test F1 | shift F1 | 변화 |
|---|---|---|---|
| 이용·냄새 | 0.815 | 0.800 | 유지 |
| 손 씻기·습기 | 0.741 | 0.750 | 유지 |
| 동파 1시간 | 0.852 | 0.836 | 유지 |
| 동파 3시간 | 0.690 | 0.675 | 유지 |
| 누수 | 0.862 | 0.741 | 정밀도 하락 (0.87 → 0.65) |
| 창문 열림 | 0.359 | 0.406 | 오름 |
| 흡연 (행 단위) | 0.602 | 0.459 | 하락 (연기 절반) |
| 흡연 후 잔류 | 0.735 | 0.590 | 하락 |
| 청소 제품 | 0.693 | 0.612 | 하락 |
| 문 열림 | 0.401 | 0.285 | 하락 (복도 차이 방향이 반대) |

장치의 물리 조건이 바뀌어도 습기·이용·동파 판정은 거의 그대로입니다. 가스 반응의 크기(흡연 연기 양, 센서 감도)와 문의 복도 조건에 기대는 항목은 떨어집니다. 실제 설치 장소가 학습 세계와 다르면 이 항목들부터 다시 보정해야 합니다.

### 6.4 온습도만 쓸 때와 비교 (문 열림을 온습도로 판별할 수 있나)

같은 방법으로 **온습도·시간 특징 33개만** 써서 학습한 모델과 비교했습니다(시험 장치).

| 항목 | 온습도만 AUC | 온습도만 F1 | 전체 센서 AUC | 전체 센서 F1 |
|---|---|---|---|---|
| 문 열림 | 0.803 | 0.318 | 0.862 | 0.401 |
| 창문 열림 | 0.913 | 0.320 | 0.917 | 0.359 |
| 환기 변화 | 0.650 | 0.082 | 0.821 | 0.313 |
| 손 씻기·습기 | 0.960 | 0.694 | 0.979 | 0.741 |
| 젖은 바닥 | 0.921 | 0.512 | 0.927 | 0.541 |
| 누수 | 0.988 | 0.854 | 0.991 | 0.862 |
| 수도 사용 | 0.903 | 0.466 | 0.943 | 0.537 |
| 동파 1시간 | 0.984 | 0.872 | 0.979 | 0.852 |
| 동파 3시간 | 0.952 | 0.720 | 0.954 | 0.690 |

- **문 열림은 온습도만으로도 일부 판별됩니다**(AUC 0.80, F1 0.32). 이 세계에서는 문이 열리면 복도 공기가 들어와 온습도가 변하기 때문입니다. 가스 센서를 더하면 F1이 0.40으로 오릅니다. 문이 열리면 가스가 빨리 빠지고, 사람이 드나들며 냄새가 생기기 때문입니다. 분포 이동 장치에서는 온습도만 F1 0.17, 전체 0.29로 떨어집니다. 복도와의 온습도 차이가 작거나 방향이 다르면 온습도 신호가 약해집니다.
- 누수, 동파, 손 씻기, 젖은 바닥, 창문은 **온습도만으로 거의 같은 성능**이 납니다. 가스 센서 없이도 이 항목들은 쓸 수 있습니다.
- 동파는 온습도만 쓴 모델이 약간 더 좋습니다(F1 0.87 대 0.85). 가스 특징이 동파에는 도움이 안 되고 잡음이 되는 것으로 보입니다. 항목별로 특징을 고르면 더 나아질 수 있습니다(7.3절).
- 환기 변화는 가스(빠지는 속도)가 있어야 판별됩니다(F1 0.08 → 0.31).

### 6.5 속도와 크기

- 모델 파일 15MB (16개 모델, 압축).
- 판정 한 번: 모델 예측 약 45ms + 특징 계산 수십 ms (4코어). 15초마다 한 번 판정하므로 한 컴퓨터(4코어)에서 장치 100대 이상을 처리할 수 있습니다.
- 전체 학습 약 50분, 임계값·흡연 규칙 재선택(`retune`) 약 20분, 자체 검사 약 3분 (4코어).

## 7. 앞으로 튜닝하는 방법

### 7.1 다시 학습하기

```sh
python -m restroom_unified.train                       # 전체 (4코어 기준 약 50분)
python -m restroom_unified.train --quick               # 파이프라인 시험 (약 7분, 성능 판단용 아님)
python -m restroom_unified.train --train-devices 240 --days 21 --stride 6 --max-iter 600
python -m restroom_unified.retune                      # 재학습 없이 임계값·흡연 규칙만 다시 고르기 (약 20분)
python -m restroom_unified.check                       # 학습 후 자체 검사
```

| 옵션 | 기본값 | 바꾸면 |
|---|---|---|
| `--train-devices` | 120 | 장치가 많을수록 장치 간 차이에 강해집니다. 시간은 거의 비례해서 늘어납니다 |
| `--eval-devices` | 40 | 보정·시험 장치 수. 늘리면 임계값과 성능 추정이 안정됩니다 |
| `--days` | 14 | 장치당 기간. 계절·드문 사건(누수, 동파)이 더 많이 들어갑니다 |
| `--stride` | 8 | 학습 표본 간격. 줄이면 행이 늘어 정밀해지지만 느려집니다 |
| `--max-iter` | 400 | 반복 횟수 상한. 보정 AP가 400에서 최고였던 항목(5.3절 표)은 늘리면 더 좋아질 수 있습니다 |
| `--out` | `models/unified` | 결과 폴더. 실험할 때는 다른 폴더로 저장해 비교하세요 |

학습할 때는 **항상 보정 장치로 고르고, 시험 장치는 마지막에 한 번만** 보세요. 시험 결과를 보고 다시 고치면 시험 성능이 실제보다 좋게 나옵니다.

### 7.2 하이퍼파라미터

`train.py`의 `BASE_PARAMS`, `LEAF_GRID`, `LEAF_PROBE_LABELS`에서 바꿉니다.

| 파라미터 | 지금 | 키우면 | 줄이면 | 권장 탐색 범위 |
|---|---|---|---|---|
| `learning_rate` | 0.08 | 빨리 배우지만 과적합·불안정 | 안정적이지만 반복이 더 필요 | 0.03~0.15 (줄이면 `--max-iter`를 늘릴 것) |
| `max_iter` (상한) | 400 | 더 복잡한 패턴 | 덜 복잡 | 보정 AP가 상한에서 최고면 늘림 |
| `max_leaf_nodes` | 63 | 트리 하나가 더 세밀(상호작용 많이) | 단순, 일반화 쉬움 | 15~127 |
| `min_samples_leaf` | 100 | 과적합 줄임, 드문 항목에 둔감 | 세밀하지만 과적합 위험 | 20~500 |
| `l2_regularization` | 1.0 | 잎 값을 줄여 안정 | 덜 규제 | 0~10 |
| `max_bins` | 255 | (최대 255) | 빠르지만 거칠게 | 63~255 |
| `max_features` | 1.0 (모두) | — | 분할마다 일부 특징만 써서 다양성↑ (랜덤 포레스트처럼) | 0.5~1.0 |
| `class_weight` | balanced | — | `None`이면 확률이 실제 비율에 가까워짐(임계값은 다시 고름) | balanced / None |

**탐색 방법 제안**

1. 항목마다 따로 잎 노드 수를 고르기: 지금은 4개 항목 평균으로 하나를 골랐습니다. `fit_label`을 항목별 격자로 돌리면 항목마다 맞는 값을 쓸 수 있습니다(시간은 격자 크기만큼 늘어남).
2. 무작위 탐색: 위 표의 범위에서 20~50개 조합을 무작위로 뽑아 보정 AP로 비교합니다. 격자보다 효율적입니다.
3. 학습 곡선: `--train-devices`를 30, 60, 120, 240으로 바꿔 보정 AP가 계속 오르는지 봅니다. 더 이상 오르지 않으면 데이터가 아니라 센서·특징의 한계입니다.

### 7.3 특징

`features.py`의 `compute_features`에서 바꿉니다. 바꾸면 기존 모델 파일은 쓸 수 없습니다(불러올 때 특징 이름이 다르면 오류). 반드시 다시 학습하세요.

- **창 길이:** `W1M`~`W6H` 상수. 예를 들어 문 열림처럼 짧은 사건은 30초 창(2행)을 더하면 도움이 될 수 있습니다.
- **버퍼:** 가장 긴 창을 늘리면 `BUFFER_ROWS`도 그만큼 늘려야 실시간 계산이 같아집니다.
- **중요도 확인:** 어떤 특징이 실제로 쓰이는지 보려면 보정 장치에서 순열 중요도를 계산합니다.

```python
from sklearn.inspection import permutation_importance
result = permutation_importance(model.models["door_open"], x_cal, y_cal, scoring="average_precision", n_repeats=3)
```

중요도가 0에 가까운 특징은 빼도 됩니다. 반대로 특정 항목이 약하면 그 사건의 물리적 특징(길이, 모양, 다른 센서와의 관계)을 새 특징으로 만들어 보세요.

### 7.4 임계값 (다시 학습하지 않고)

임계값은 모델 파일 안의 `thresholds`에 있습니다. 예를 들어 누수를 더 민감하게 하려면:

```python
import joblib
bundle = joblib.load("models/unified/unified_model.joblib")
bundle["thresholds"]["leak_active"]["alarm"] = 0.3          # 낮출수록 재현율↑, 오경보↑
joblib.dump(bundle, "models/unified/unified_model.joblib", compress=3)
```

보정 장치로 기준을 정해 다시 고르려면 `retune`을 씁니다. 모델은 그대로 두고 임계값과 흡연 규칙만 바꿔 저장하고, 시험 결과도 다시 계산합니다.

```sh
python -m restroom_unified.retune --watch-precision .6          # 주의 단계를 덜 민감하게 (정밀도 60% 이상)
```

고르는 기준 자체를 바꾸려면 `pipeline.pick_thresholds`를 고칩니다(`best_f1_threshold`, `watch_threshold`, `recall_threshold`).

| 기준 | 맞는 항목 |
|---|---|
| F1 최대 (지금) | 정밀도와 재현율을 같이 볼 때 |
| 재현율 목표 (예: 90%, 95%) | 놓치면 큰일인 항목: 누수, 동파, 흡연 |
| 정밀도 하한 (예: 80% 이상 중 재현율 최대) | 오경보가 귀찮은 정보성 항목: 문 열림, 이용·냄새 |
| 비용 기반 (놓침 비용 × 놓친 수 + 오경보 비용 × 오경보 수 최소) | 관리자 대응 비용을 알 때 |

실측 데이터가 생기면 **임계값부터 실측으로 다시 고르는 것**이 가장 싸고 효과가 큽니다.

### 7.5 흡연 알림 규칙

- 오경보 상한: `train.py`의 `FALSE_LIMITS` (경보 0.05, 의심 0.25, 장치·일당). 낮추면 알림이 엄격해지고 감지율이 떨어집니다.
- 탐색 격자: `pipeline.py`의 `SMOKING_THRESHOLDS`(0.5~0.995)와 `SMOKING_PERSISTENCE`((m, window) 쌍), 해제 지연 `clear`(8번 = 2분).
- 다시 학습하지 않고 바꾸기: `python -m restroom_unified.retune --alarm .03 --suspect .2`

### 7.6 등급 규칙

`rules.py` 상단의 상수입니다.

| 상수 | 지금 | 뜻 |
|---|---|---|
| `LEAK_CONFIRM_MINUTES` | 30 | 청소·손 씻기 중이어도 이 시간 넘게 이어지면 누수 긴급 |

| `WINTER_MONTHS` | 12, 1, 2 | 창문 열림을 "주의"로 올리는 달 |

### 7.7 데이터 세계의 가정

실측 데이터가 생기면 가장 먼저 맞춰야 할 부분입니다. 모델 성능은 합성 세계가 현실과 얼마나 비슷한지에 달려 있습니다. `world.py`의 `sample_devices`(장치 파라미터)와 `_schedule`(사건)에서 바꿉니다.

| 현실에서 잴 것 | 맞출 파라미터 |
|---|---|
| 문이 열릴 때 온습도가 얼마나, 얼마나 빨리 변하나 | `k_door`(교환율), `door_dt`·`door_dh`(복도와의 차이), `k_hdoor` |
| 창문이 열릴 때 | `k_win`, 바깥 날씨 |
| 냄새·청소제·소독제가 MQ-7을 얼마나 올리나 | `odour(...)`의 CO 비율(m1 × 비율), `bodor`(MQ-7의 냄새 교차 감도) |
| 흡연 때 두 센서가 얼마나 오르나 | 흡연 주입량(`plume × 0.8~2.0`), CO 비율(0.2~1.0), `bco`, `a135` |
| 손 씻기·물청소 습도 변화 | `water(...)`의 주입량, `kh`, 젖은 바닥 목표·시간 상수(0.006) |
| 가스가 빠지는 속도 | `k0`, `k_fan`, `k_gdoor`, `k_gwin` |
| 사건 빈도 | `use_rate`, `smoke_rate`, 청소 횟수, `leak_rate`, 창문 `win_rate` |

**맞추는 절차**

1. 실제 화장실에서 사건마다 센서 반응을 기록합니다(문 열고 닫기, 손 씻기, 청소 등을 직접 하고 시각을 적음).
2. 같은 사건을 시뮬레이션해 반응 크기·속도가 실측 범위 안에 들어오도록 위 파라미터 범위를 고칩니다. `plot_dataset.py`의 "사건별 센서 변화" 그래프와 실측을 나란히 놓고 비교하면 쉽습니다.
3. 데이터를 다시 만들고(`export_dataset.py`) 다시 학습합니다.

### 7.8 실측 데이터가 생기면 (권장 순서)

| 단계 | 할 일 | 효과 |
|---|---|---|
| 1 | 실측 행에 정답 표시 (사건 시각 기록) | 평가가 가능해짐 |
| 2 | 지금 모델로 실측 평가 | 합성 → 실측 차이 확인 |
| 3 | 실측으로 임계값만 다시 고르기 (7.4절) | 가장 싸고 효과 큼 |
| 4 | 세계 가정 맞추기 (7.7절) 후 다시 학습 | 차이가 큰 항목 개선 |
| 5 | 실측 + 합성 섞어서 학습 (실측 행 가중치를 높게) | 실측 패턴 직접 학습 |
| 6 | 장치 단위로 나눠 평가 (같은 장치가 학습·시험에 동시에 들어가지 않게) | 새 장치에서의 성능을 정직하게 추정 |

## 8. 원래 프로젝트의 모델과 비교

| | 시설 AI | 흡연 판정기 | Duo Fusion (상황 AI) | **통합 모델 (이 문서)** |
|---|---|---|---|---|
| 판정 | 창문, 수도, 누수, 동파 1·3시간 | 흡연 경보·의심 | 일상 상황 11개 | 16개 전부 |
| 알고리즘 | HistGradientBoosting 5개 | 소형 그래디언트 부스팅 + 누적합(CUSUM) 알림 | XGBoost 3개 + 신경망 3개, 5단계 융합 | HistGradientBoosting 16개 + 지속 규칙 |

| 특징 | 22개 | 25개 | 1,232개 | 56개 |
| 튜닝 | 반복 180, 학습률 0.075, 잎 31, 임계값 F1 최대·재현율 90% | 오경보 상한 아래 감지율 최대인 CUSUM 규칙 | 좌표 탐색으로 라벨별 결합 비율·임계값 | 5장 |

## 9. 한계

- **모두 합성 데이터 결과입니다.** 실제 화장실에서는 성능이 다를 수 있습니다. 특히 문 열림의 온습도 영향, 냄새·청소제의 MQ-7 반응은 공학적 가정입니다.
- **DHT11은 0℃ 아래를 읽지 못합니다.** 영하 구간의 동파는 센서값으로 구분되지 않습니다.
- **전자담배·궐련형 전자담배는 못 잡습니다.** CO가 거의 없어 MQ-7이 반응하지 않습니다.
- **MQ-7 값이 없으면 흡연 판정이 거의 불가능합니다.** 히터 전환 회로가 필요합니다.
- **항목별 독립 모델입니다.** 항목 사이의 관계(예: 청소+젖은 바닥이면 청소 제품도 켜짐)는 등급 규칙에서만 씁니다. 분류기 사슬(classifier chain)처럼 앞 항목의 확률을 다음 항목의 입력으로 주는 방법으로 개선할 수 있습니다.
