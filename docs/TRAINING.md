# 학습 과정

이 모델을 실제로 어떻게 학습했는지, 순서대로 적은 기록입니다. 알고리즘 자체의 설명과 튜닝 방법은 [ALGORITHMS.md](ALGORITHMS.md)에 있습니다.

> 모든 학습·평가는 합성 데이터로 했습니다. 실제 화장실 측정은 0행입니다.

## 1. 환경

| 항목 | 값 |
|---|---|
| CPU / 메모리 | 4코어 / 15GB |
| Python | 3.13.16 |
| 라이브러리 | numpy 2.5.3, pandas 3.0.5, scikit-learn 1.9.1, joblib 1.6.0, matplotlib 3.11.2 (그래프만) |
| 학습일 | 2026-10-12 |

모델 파일(`unified_model.joblib`)은 scikit-learn 1.9.1로 저장했습니다. 다른 버전에서는 불러오지 못하거나 결과가 조금 다를 수 있습니다.

## 2. 전체 흐름

```
① 합성 데이터 만들기     world.generate(seed*1000 + 묶음, 20대, 14일)        장치마다 15초 행 80,640개
② 특징 계산             features.compute_features                          행마다 특징 56개
③ 학습 표본             학습 장치 120대, 8행마다 1행                          1,191,600행
④ 잎 노드 수 고르기       대표 4개 항목, 30만 행, 15·31·63 비교                → 63
⑤ 항목별 학습            16개 항목, 최대 400번 반복, 보정 장치 AP로 반복 횟수 선택
⑥ 비교용 모델            온습도 특징 33개만 쓰는 모델 9개 (평가 전용)
⑦ 임계값·흡연 규칙        보정 장치 40대의 모든 행(317만 행)
⑧ 시험                  test 40대, shift 40대 (각 317만 행), 한 번만 평가
⑨ 자체 검사              check.py 12개 항목
```

## 3. 데이터

| 구분 | 시드 | 장치 | 행 | 쓰임 |
|---|---|---|---|---|
| train | 1 | 120대 × 14일 | 9,676,800 (학습에는 8행마다 1행) | 학습 |
| calibration | 2 | 40대 × 14일 | 3,225,600 | 반복 횟수·임계값·흡연 규칙 선택 |
| test | 3 | 40대 × 14일 | 3,225,600 | 최종 시험 |
| shift | 4 | 40대 × 14일 | 3,225,600 | 분포 이동 시험 (다른 조건) |

- 장치 20대씩 묶어 시드 `구분 시드 × 1000 + 묶음 번호`로 만듭니다. 예: train 첫 묶음은 시드 1000, 둘째는 1001.
- 학습·평가에서는 장치마다 처음 2시간(480행, 예열)과 마지막 3시간(720행, 동파 미래 정답 없음)을 뺍니다. 그래서 평가 행은 구분마다 3,177,600행입니다.
- 내보낸 데이터는 [`data/unified_world_v1/`](../data/unified_world_v1/README.md)에 있고, 다시 만든 결과와 같은지 확인했습니다.

## 4. 학습 설정

| 설정 | 값 |
|---|---|
| 알고리즘 | scikit-learn `HistGradientBoostingClassifier`, 항목마다 이진 분류기 1개 (16개) |
| 학습률 | 0.08 |
| 잎 노드 수 | 63 (15·31·63 중 선택) |
| 잎 최소 행 수 | 100 |
| L2 규제 | 1.0 |
| 클래스 가중치 | balanced |
| 반복 횟수 | 최대 400, 항목별로 보정 장치 AP가 가장 좋은 횟수에서 자름 |
| 조기 종료 | scikit-learn 내장 기능은 끔 (무작위 행 분할이라 같은 장치가 섞임). 대신 다른 장치(보정)로 고름 |
| 난수 | `random_state=0`, 표본 추출 시드 0 |

### 1차 결과에서 고친 두 가지

1. **흡연 알림 규칙:** 1차 탐색은 임계값 최대 0.9였는데, 클래스 가중치 때문에 흡연이 아닌 행도 0.9를 넘는 경우가 많아 오경보 기준(경보 0.05, 의심 0.25 / 장치·일)을 맞추는 규칙이 없었습니다. 탐색 범위를 임계값 0.995, 지속 조건 16번 중 14번까지 넓혔습니다.
2. **동파 "주의" 기준:** 1차는 "재현율 90% 이상인 가장 높은 임계값"이었는데, 동파 1시간은 0.000이 되어 항상 "주의"가 켜질 상태였습니다. "정밀도 50% 이상 중 가장 민감한 임계값"으로 바꿨습니다.

두 가지 모두 모델(트리)은 그대로 두고 `python -m restroom_unified.retune`으로 다시 골랐습니다. 지금의 `train.py`는 고친 방법을 이미 쓰므로, 다시 학습하면 한 번에 같은 결과가 나옵니다.

## 7. 다시 만들기

```sh
pip install -r requirements.txt
python -m restroom_unified.train                   # ③~⑧ 전체 (약 50분, 4코어). 결과: models/unified/
python -m restroom_unified.check                   # 자체 검사 (약 3분)
python -m restroom_unified.export_dataset --out data/unified_world_v1     # 학습 데이터 내보내기 (약 1분)
python -m restroom_unified.plot_dataset --data data/unified_world_v1 --out data/unified_world_v1/graphs
```

- 다른 폴더에 저장해 비교하려면 `--out`을 쓰세요. 예: `python -m restroom_unified.train --out runs/try1`
- 파이프라인만 빨리 확인하려면 `--quick` (약 7분, 성능 판단용 아님). 결과는 `models/unified_quick/`에 저장되어 실제 모델을 덮어쓰지 않습니다.
- 임계값·흡연 규칙만 바꾸려면 `python -m restroom_unified.retune` (약 20분).
